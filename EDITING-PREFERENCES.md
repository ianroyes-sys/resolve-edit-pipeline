# Editing preferences

Read before every edit, alongside `WORKFLOW.md`. Direct corrections from the client or editor outrank tutorials, inferred style and old edit plans. Keep this file for durable preferences; job-specific corrections go in that job's `feedback.json`.

## Example durable rules

These came out of real review rounds and are kept as a starting point:

- Never include camera resets, repositioning, readiness movement, heavy shake or accidental reframing. Good audio does not excuse bad picture. Trim before the movement or reject the range. Stabilization doesn't fix an operator moving to the next shot.
- The stable first part of a shot can be used while the rest is rejected. Record rejected source intervals separately.
- A shorter, clean story beats preserving a full speech fragment or a target runtime.
- Each shot must add something. Consecutive coverage with the same purpose slows the edit.
- Include the people who matter, not only the easiest speech excerpts. A speaker can appear under music without using an unsuitable quote.
- Keep the event's tone. A shot rejected for one event's tone is not banned everywhere.

## Learning after every review

1. Save the exact correction with the affected version, source clip and range, or timeline marker in the job's feedback file. Separate global preferences from event-specific choices and unconfirmed guesses.
2. Explain the editorial cause and turn the correction into a concrete selection or delivery check.
3. Apply it to the current revision and run the check against the new plan and the rendered result.
4. Update this file only for durable preferences. Record superseding corrections instead of erasing old evidence.
5. At the next job, read this file before culling and carry the relevant checks into its verification report.
6. When a real technique gap remains, study tutorials or supplied references, and log the URL, what was actually viewed, the lesson and a before/after trial. Never claim an inaccessible video was watched.
